## Part 1: Run Comparison Screenshot

For this I swapped out the RandomForest + IRIS starter script and used an `MLPClassifier` on **MNIST** instead. I ran 6 experiments sweeping two hyperparameters, `learning_rate_init` ∈ {0.0001, 0.001, 0.01} and `batch_size` ∈ {64, 256}, so a 3×2 grid.

Everything else was held fixed: one hidden layer of 100 units, 20 epochs, seed 42, 16,000 train / 4,000 validation split of MNIST-784.

The important change from the starter script is that I log `train_loss` and `val_accuracy` at **every epoch** using `step=epoch`, instead of one number at the end. Without that you only get two endpoints per run, and you can't actually see whether a model is overfitting or not.

## Part 2: Written Analysis

Across the 6 runs (`learning_rate_init` × `batch_size` sweep on the MLP), the best performing run was **mlp-run-6** (lr=0.01, batch_size=256), which hit `val_accuracy` = **0.9708** at epoch 19.

It won because lr=0.01 gets most of the way there within the first three epochs, and the larger batch smooths out the gradient noise that a big learning rate would otherwise cause. You can see that noise in **mlp-run-5**, same lr but batch_size=64, where `train_loss` bounces around (0.0874, 0.0896, 0.0702, 0.0780) instead of falling cleanly.

The clearest **overfitting evidence** is in **mlp-run-3** (lr=0.001, batch_size=64). Between epoch 13 and epoch 20, `train_loss` drops from 0.0361 to 0.0111 — a 69% reduction — but `val_accuracy` barely moves, 0.9635 → 0.9637. So the model keeps fitting the training set harder and gets basically nothing back on validation, which is the point where it stops generalizing and starts memorizing. mlp-run-6 shows a milder version: `train_loss` ends at 0.0015, which is near total memorization.

Between the two hyperparameters, **`learning_rate_init` clearly has the bigger effect**. Averaging `best_val_accuracy` per value:

| Hyperparameter | Values → mean `best_val_accuracy` | Spread |
|---|---|---|
| `learning_rate_init` | 0.9228 → 0.9601 → 0.9668 | **4.40 pp** |
| `batch_size` | 0.9531 → 0.9466 | 0.65 pp |

That is roughly **7× more**. They do interact though: at low lr the smaller batch wins, but at lr=0.01 the bigger one does.

## Part 3: MLflow Logging Code

Here are the exact `mlflow.log_param` and `mlflow.log_metric` calls I added on top of the starter script. The parameters are logged once before training; the metrics are logged inside the epoch loop with `step=epoch`, which is what produces the curves in Figure 2.

```python
def train_and_log(hidden_layer_sizes=(100,), learning_rate_init=0.001,
                  batch_size=200, max_iter=20, run_name=None):
    with mlflow.start_run(run_name=run_name):
        # --- parameters (logged once, before training) ---
        mlflow.log_param("hidden_layer_sizes", str(hidden_layer_sizes))
        mlflow.log_param("learning_rate_init", learning_rate_init)
        mlflow.log_param("batch_size", batch_size)
        mlflow.log_param("max_iter", max_iter)
        mlflow.log_param("seed", SEED)

        model = MLPClassifier(
            hidden_layer_sizes=hidden_layer_sizes,
            learning_rate_init=learning_rate_init,
            batch_size=batch_size,
            random_state=SEED,
            max_iter=1,          # epoch loop is driven manually below
            warm_start=True,
        )

        train_losses, val_accs = [], []

        # --- metrics: one point per epoch via step= ---
        for epoch in range(1, max_iter + 1):
            model.partial_fit(X_train, y_train, classes=CLASSES)

            train_loss = float(model.loss_)
            val_pred   = model.predict(X_val)
            val_acc    = float(accuracy_score(y_val, val_pred))
            train_acc  = float(accuracy_score(y_train, model.predict(X_train)))
            f1         = float(f1_score(y_val, val_pred, average="macro"))

            mlflow.log_metric("train_loss", train_loss, step=epoch)
            mlflow.log_metric("val_accuracy", val_acc, step=epoch)
            mlflow.log_metric("train_accuracy", train_acc, step=epoch)
            mlflow.log_metric("f1_macro", f1, step=epoch)
            mlflow.log_metric("generalization_gap", train_acc - val_acc, step=epoch)

            train_losses.append(train_loss)
            val_accs.append(val_acc)

        # --- summary metrics: one value per run, used to sort the table ---
        mlflow.log_metric("final_train_loss", train_losses[-1])
        mlflow.log_metric("final_val_accuracy", val_accs[-1])
        mlflow.log_metric("best_val_accuracy", max(val_accs))
        mlflow.log_metric("best_epoch", int(np.argmax(val_accs)) + 1)

        mlflow.set_tag("team", "data-science")
        mlflow.set_tag("model_type", "MLP")
        mlflow.sklearn.log_model(model, name="model",
                                 serialization_format="pickle")

        return mlflow.active_run().info.run_id
```

The `step=epoch` argument is the key part. Without it each metric is a single number and the `train_loss` vs `val_accuracy` trend asked for in Part 2 doesn't exist.
